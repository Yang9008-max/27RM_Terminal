# 2027 RMUL 3V3 自定义终端调研

开发进展：第一阶段已实现控制度、固定血量槽位和模拟器到终端状态链路，验收见 [第一阶段说明](../../development/rmul2027-data.md)。下文保留调研阶段的结论及当时边界，其他2027通信和RMUL界面仍待后续适配。

核查日期：2026-11-11。用户已确认以 **RMUL 3V3** 为主，基于复旦大学星云 EGA 的 Qt 框架继续开发。本轮仅调研、归档和准备讨论，未修改通信、业务状态或界面实现。

## 当前结论

1. 保留复旦 Qt/C++/QML、MQTT/Protobuf、FFmpeg 视频和独立模拟器框架。当前源码快照为 `e291f2f65f5a5924509e4e2fe1b148ff9d4b24af`，其协议基线是 **2026 V2.0.0**，且上游清单仍标注对齐进行中。
2. 用户提出的“改 2027 通信、换 RMUL 界面”方向正确；两者中间必须补上 **RMUL 比赛状态与角色映射**。只改 `.proto` 或图片，会留下血量错位、控制度缺失、旧机制误显示等问题。
3. RMUL 3V3 每队重装 1 号、步兵 3 号、哨兵 7 号，比赛 5 分钟，双方初始控制度各 600，场地 12m×8m。以控制度为主判胜，不能沿用 RMUC 基地/前哨站界面。[规则依据](sources.md#官方资料)
4. 2027 `GlobalUnitStatus` 新增 `total_CP_ally=15`、`total_CP_enemy=16`；血量数组仍按己方 1/3/4/7、对方 1/3/4/7 定义，**线格式里的 4 号槽位不能因 3V3 只有三台车就直接删掉**。实际 RMUL 是否仍发满 8 槽，须抓包确认。
5. 小机械臂可以作为这套终端的有线输入：本地网口数据进入 Qt 输入适配器，再封装 `CustomControl`，由官方链路转为机器人端 `0x0311`。这条链路还需要机器人固件接收适配与真实设备验证。
