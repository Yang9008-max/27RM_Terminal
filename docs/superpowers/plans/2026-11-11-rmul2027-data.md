# RMUL 2027 比赛数据第一阶段 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 模拟器发送 GlobalUnitStatus 后，终端准确保存双方控制度及固定 1/3/4/7 槽位的血量，区分字段缺失与真实零值。

**Architecture:** 沿用单一 Protobuf schema、MQTT → NetworkManager → GameData 链路。控制度保存为红/蓝两组 uint32 值及接收有效标记；按终端机器人 ID 将 ally/enemy 转成红/蓝。血量严格使用官方八槽顺序，不按数组长度猜阵容。

**Tech Stack:** Qt 6 / C++17、Protobuf、Python 3.13、Paho MQTT、Mosquitto、QtTest、unittest。

## Global Constraints

- 用户要求重大改动前先提交并打版本；检查点 `rmul2027-pre-01-2027-data`，工作分支 `rmul2027/01-2027-data`。
- 本阶段只实现比赛数据链路；RMUL 界面与完整规则模拟器留待后续阶段。
- 官方依据：2027 通信协议 V1.0.0（20261029）§2.2.4，印刷 p54–55 / PDF p55–56。
- 血量槽位固定为己方 1/3/4/7、对方 1/3/4/7。缺失数组保持上次快照；非八项的非空数组拒绝，不能猜测裁剪后的顺序。
- repeated 字段没有逐槽 presence；数组里的 0 是真实值。控制度缺失不覆盖已经收到的值，首次缺失保持未知。
- 其他 2026 消息、旧前哨字段命名/语义尚未完成迁移；协议清单必须明确局部迁移范围，不能声称全部支持 2027。
