# 2027 RMUL 3V3 战术页迁移

日期：2026-11-14。基线：`rmul2027-pre-06-tactical-20261114`（`10acc29`）。
开发分支：`rmul2027/06-tactical`。

## 问题与实现

用户截图是独立的旧战术页。它经 TacticalAnalyzer 显示固定的 1/2/3/4/6/7 阵容、
英雄/工程/空中角色、基地/前哨站、科技/侵垒/经济和旧 RMUC 地图；
前面公共 HUD、P 面板与结算迁移不会自动改变这个入口。

`GameData::rmulTacticalData()` 复用已有 `settlementSnapshot()` 的颜色映射与存在性信息，
向 QML 提供红蓝双方控制度、总攻击伤害、三车血量合计和固定 1/3/7 阵容。
缺失为 invalid QVariant，QML 显示 `—`；收到的 0 如实显示。
只有三车血量都已收到才提供合计，4 号线格式槽位继续解析但不进入合计。
不使用默认 600 血量、静态旧血量或旧分析器 Mock 作为替代，也不根据血量推断在线/离线。

战术入口改用独立的 RMUL 头部、阵容、对比与场地组件，保留切角框、红蓝配色、
控制度/统计条过渡动画、血量归零提示、相机帧刷新、Ctrl+Y 布局和 M 键展开。
比赛时钟直接绑定服务端状态，未收到为 `--:--`，收到超出 300 秒的值也不会偷偷截断。
页内不再消费旧经济分析、决策建议、预测曲线、复活金币和旧地图坐标。
没有相机帧时显示等待，不再用旧机器人照片充当直播画面。

`MainWindow` 不再接入旧分析器根据回血推断的金币复活播报；
自动战术定时弹窗停止使用旧空中/能量机关/飞镖时间表。
显式开发预览入口及旧模块源文件保留，供独立历史测试和后续迁移使用。

## 场地示意的依据与边界

依据本地官方《RoboMaster 2027 机甲大师高校联盟赛比赛规则手册》V1.0.0（2026-10-15），
PDF 第 23–24 页（印刷页 22–23）的图 3-1、3-4：场地 12m×8m、
两端补给区、双方高地控制区、中央控制区。来源与文件校验索引见
[2027 调研来源](../research/rmul2027/sources.md)。

本轮用 QML 自绘结构示意，不复制官方 PDF 图像进入 Git。
区域相对排布参考规则，尺寸/位置不是测绘坐标，没有声明通道、工作台或隧道的精确几何。
蓝方视角整体旋转，同时保持文字正向；展开页与缩略页一致。
图中不显示机器人位置或实时占领颜色，明确标注“非测绘地图 · 未接入实时定位 / 占领状态”。
不能把旧 28×15 地图归一化坐标套到 12×8 场地，也没有把统计伤害误作逐车定位依据。

## 验证

旧页在新增验收中复现两项失败：缺少 RMUL 投影、仍走旧战术数据。
迁移后针对性测试覆盖：

- 1/3/4/7 固定线格式，红 923 / 蓝 1050 的三车合计，以及 4 号槽位排除。
- 红蓝视角、uint32 上限、0、空增量包、非法部分血量数组、身份切换与重置。
- 实际 QML 只生成双方 1/3/7 六张卡片，显示血量、控制度和服务端时钟。
- Ctrl+Y 对应布局模型切换，M 键展开/销毁和 800×600 到 4K/超宽屏几何。
- 相机帧 revision/FPS 路径与独立图像提供器，不依赖旧战术 Mock 刷新。

Windows UCRT64 Release 完整构建及 CTest 33/33 通过（第一轮 39.62 秒）。
展开提示位置修正后最终完整重跑仍为 33/33 通过，37.49 秒；构建内资源检查通过。
桌面验收使用 agent-desktop / agent-desktop-windows：

- 实际窗口显示红方控制度 600、蓝方 590，双方仅各三车，血量合计 923 / 1050。
- 在未开始阶段写入零控制度、红步兵/蓝哨兵零血量，页面显示 0 与归零提示；合计均为 800。
- 通过 P 的 5 + Enter 正式登录蓝方步兵后，左侧为蓝方、右侧为红方，血量与配色一致，示意图旋转。
  下拉框仅是待确认选择，验收时必须确认登录，并同步模拟器话题的己方视角，不能只改模拟器身份。
- Ctrl+Y 在地图/相机主画面间切换，M 展开/返回正常；无相机帧显示等待。
- 展开图的返回提示曾与底部说明相交，已移到顶部，修正后重新构建和执行完整测试。

截图保存在忽略的 `tmp/rmul-tactical-*.png`；没有将窗口内其他应用画面纳入资料。

## 后续边界

本阶段针对战术页及其自动提示入口；旧操作页小地图、长按 TAB、H 兑换、
能量机关操作和其他上游事件逻辑不因此宣告完成 RMUL 迁移。
实机裁判端、机器人定位、实时控制区状态、图传硬件和实际听感仍需专项验收。
