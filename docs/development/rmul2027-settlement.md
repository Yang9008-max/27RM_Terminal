# 2027 RMUL 3V3 判胜与结算迁移

## 规则与版本

开发分支 `rmul2027/03-settlement`；改动前基线 `639fd2c`，已保存带说明标签 `rmul2027-pre-03-settlement-20261113`。本次在复旦 Qt 框架内替换结算链路，不改写历史，不推送远程。

依据仓库已归档的 RMUL 规则 V1.0.0（20261015）PDF38–39，以及通信协议 V1.0.0（20261029）PDF54；文件位置和哈希见[来源索引](../research/rmul2027/sources.md)。2026-11-13尝试访问官方动态页面，网页工具没有返回正文，因此没有据此宣称线上规则已更新。

- 一方控制度归零且另一方非零，非零方立即获胜。
- 五分钟结束时依次比较：控制度、全队总攻击伤害、全队机器人总剩余血量，仍相同则平局。
- 3V3 血量只统计重装1、步兵3、哨兵7。协议4号槽位仍正常编解码，但不计入结算总血量。
- `GameStatus.game_result`：0平局、1红胜、2蓝胜；只在阶段5有效。255或缺失表示未确认，不能显示为平局。
- `end_reason`：1基地摧毁（兼容协议枚举）、2控制度、3攻击伤害、4总剩余血量、5平局、6异常终止、7主裁判手动判定。RMUL模拟器常规裁决只生成2–5；收到官方6/7时客户端明确呈现。

## 根因和实现

旧模拟器优先比较基地、前哨站，血量切片还把红蓝槽位混在一起；客户端忽略官方结果字段，以累计比分或比分增量推算本局赢家。旧结算面板沿用六车、建筑、能量机关及未实际下发的单车伤害统计。这三处共同造成用户截图中红600、蓝590而显示蓝胜的问题。

现在模拟器通过 `_adjudicate_rmul()` 集中裁决，结果和原因来自同一份数据；只成功结算一次才累计比分。控制度缺失、双方同时为0等非法场景保留255，不凭空授予胜负。缺失判据补齐后可以完成一次结算。已经确认的结果不被后续编辑再次计分；如需重演，先进入新战斗阶段。

战斗默认300秒，开局双方600控制度并清理上局攻击伤害、结果和事件队列；结算保留实际战斗用时。完整演示时钟为305秒（含5秒倒计时），网页相应同步。控制度归零后，旧演示后续帧不能覆盖结算阶段。

客户端以 `GameStatus` 为本局结果唯一来源，累计比分只作系列赛信息。旧 UDP/Event 的单独结果缺少局数和结束原因，不再提前结束比赛或覆盖官方快照。optional字段在同会话同局稀疏更新中保留；显式255清空结果；换局、离开结算、断线、换身份清理相应有效性。MQTT阶段缓存也按字段存在性合并，避免稀疏结果包被解读为阶段0。

`RmulSettlementSnapshot` 为结算页提供控制度、官方uint32攻击伤害、1/3/7血量、用时、局数和比分。未知数值显示 `—`，真实0显示0。攻击伤害直接取官方 `GlobalUnitStatus.total_damage_*`，不把受伤量当作攻击伤害，也不从旧的单车统计反推。总血量须三台均已知才显示。

结算页只显示红蓝各三台机器人及上述判据，移除基地、前哨站、能量机关、工程、空中机器人、单车虚构伤害与击杀统计。主窗口统一刷新投影；同局普通统计刷新不重复开窗或播音；Esc关闭后不被后续统计包重新弹出，新局或重连后的结算可重新出现。Ctrl+R仅查看当前实际结算，不再制造演示赢家。

用户审阅了第一版静态验收表后，明确要求保留原框架的视觉与动画。已将功能成果保存为提交 `a6d7d51`，并创建视觉修改前标签 `rmul2027-pre-03-settlement-visual-20261113`。最终版复用原有红胜/蓝胜PNG序列，先播放约2秒胜利动画，再展开3V3战报；按实际经过时间选帧，卡顿时跳过过期帧，不累积播放延迟。素材缺失时直接显示战报。平局不播放某方胜利，待定不预播；结果撤回或换局会取消旧动画。统计刷新不重播，主动Ctrl+R重新打开可以重看。

战报恢复原有机器人图标、深色红蓝渐变、胜方金色WINNER标记、判胜行高亮和红蓝动态对比条。对比条按两队已知数据较大值归一化，仅用于两队比较，不表示控制度600上限或机器人血量上限。全队数据未知时不绘制假进度。原Hero图标暂沿用为重装视觉素材，文字与统计阵容已为1/3/7，不能据此认定机械臂与重装功能已适配。

桌面复核另外发现：旧战术页面切换路径会隐藏结算面板；它与数据接收无关，已移除这条可见性覆盖。结算页跨操作页/战术页都可显示，切页也不会重新打开主动关闭的战报。背景音乐在结算时停止，去除旧的“基地血量+倒计时猜测异常结束”分支；结算音效只由确认后的结果触发。

注意：协议没有为这些独立topic提供同一结算事务的编号。页面统计是本会话最新收到的官方快照，可能在结果之后补齐，不宣称为服务端冻结的最终技术统计；胜负始终不由页面统计改判。

## 全面复核边界

本次完成判胜、接收、结算页及其生命周期，不代表整个旧客户端和演示引擎已完整符合RMUL。以下仍需另一步迁移：

- 控制区占领按秒扣分、阵亡扣10控制度、落后补偿等完整自动规则。目前控制度由网页裁判面板明确输入；结算链路消费该值，不模拟控制区机制。
- 通用演示仍有RMUC地图、建筑、空中、能量机关事件；仅其战斗时钟和裁决已迁移，不能作为完整RMUL训练对局。旧复活公式仍引用420秒，需要按RMUL复活条款整体更换，不能只把常数替换为300。
- 旧TAB、战术地图、登录角色、兑换菜单、奖励提示和重装机械臂侧栏未在此步交付。此前HUD的适配及旧页面边界仍适用。
- 尚未连接实际2027官方设备、视频融合整机或赛场网络。未声称完成真实硬件或音频播放验收。
