## 规则依据

以本地已归档的中文版 V1.0.0 为依据；版本、原件及 SHA-256 见 [来源索引](../research/rmul2027/sources.md)。下列页码均为 PDF 页序：

- RMUL规则 PDF19：3号步兵底盘为血量优先/功率优先，17mm机构为冷却优先/爆发优先。赛前选择，比赛开始且选择完成后本局不能更换；默认值由裁判系统下发，客户端不自行填成确认值。
- RMUL规则 PDF21：7号哨兵须全自动运行，不能提供半自动操作切换。
- 2027通信协议 PDF61、70–71：两种步兵性能均仅有1/2，`RobotStaticStatus`性能字段、`RobotPerformanceSelectionCommand/Sync`对应字段为optional。字段缺失与显式0必须区分。

| 项目 | 原问题/用途 | 本次处理 |
| --- | --- | --- |

| 步兵底盘 | 所有角色都可设置，回执变化也会触发发送 | 仅当前已登录步兵，在已知赛前阶段1–3可选血量/功率；仅用户激活选项发送 |
| 步兵17mm机构 | 混入英雄性能，显示可能只反映本地草稿 | 仅冷却/爆发；单独展示裁判确认值，未收到时显示初始设置；预览其他身份不冒充其确认值 |
| 哨兵操作方式 | 自动/半自动对所有身份开放，并随性能设置一起发送 | 移除半自动选择；哨兵入口明确为观测，阻止该身份的键鼠控制 |
| 准备/技术暂停性能提示 | 无论角色和已收数据均提示未设置 | 只在准备阶段、当前步兵缺少完整性能时提醒；重装/哨兵及已确认步兵不提示 |
| 图传源与连接状态 | 新图传/外部通道沿用现有接收器 | 保留原接收链路和真实连接状态；未接硬件不显示连接成功 |
| 图传方向 | P信号未接入实际处理 | 禁用手动下拉，显示自动适配；未新增或宣称已完成重装旋转策略 |
| 鼠标灵敏度 | 调整键鼠控制鼠标缩放 | 保留，修正名称为鼠标灵敏度 |
| 提示音量 | 控制战斗提示和结算音效 | 保留，修正名称；实机验收关闭音频，未验收听感 |
| 背景音量 | 控制背景播放器 | 保留 |
| 视频刷新上限 | 限制视频新帧呈现；不提高图传源帧率 | 第五阶段修复原先只存值、未限流的问题，见 [本地设置验收](rmul2027-local-settings.md) |
| 自定义UI显示/隐藏/清除 | P信号未连接，原选项不会完成其宣称功能 | 禁用，显示暂不可用 |
| 准心、小地图 | 本地可见性切换 | 保留原功能；地图内容和旧阵容不是本次迁移范围 |
| 全屏/窗口化 | 本地显示模式 | 保留 |
| 温度45°C、正赛、通道0 | 固定写死，无真实数据来源 | 删除伪状态，替换为赛事标识 |

现有四列布局与颜色保留。内部身份键 `R1 - Hero` 等暂留作图传、机器人ID转换等旧代码兼容；UI展示重装，并不意味着所有含Hero的协议名、资源名都应该替换。

## 通信闭环

`QML用户选择 → MainWindow角色/登录/阶段检查 → NetworkManager枚举检查 → Command → 模拟器校验 → Sync及StaticStatus → GameData → P面板确认值`。

1. 发送端只写非零的shooter/chassis字段，0表示不请求该项，省略而不是发送重置；RMUL步兵命令不写sentry_control。旧3/4、半自动及空请求均被拒绝。
2. 接通原来只订阅却未处理的`RobotPerformanceSelectionSync`。该消息不含robot_id，归当前MQTT身份；仅3/103消费性能。
3. Sync和StaticStatus均按字段presence更新；缺失字段保留上次有效值，非法大枚举变未知，避免257截断成1。断连重连、新回合或结算后进入下一阶段清除旧性能，等待新帧。
4. 模拟器缺省参数改为None，不再把只改底盘当成同时重置发射机构；有效变更同时更新Sync和StaticStatus，避免周期广播将确认值覆盖回默认值。MQTT入口拒绝非步兵、战斗/结算阶段及旧枚举。
5. QML初始化、回执同步、身份切换不会反发性能指令；本地点击不改GameData中的确认状态。未登录、身份不匹配、比赛状态未知、战斗或结算阶段禁用性能控件。

Python生成文件使用与现有虚拟环境兼容的protoc33.2重生成：

```powershell
.deps/protoc-33.2/bin/protoc.exe -I src/network/proto --python_out=sim src/network/proto/robomaster.proto
```

字段编号和类型保持不变。不要使用原生C++工具链的较新protoc生成Python文件而不同时检查Python运行库版本。

## 边界

- 这次完成P设置和相关提示、性能通信；旧TAB、战术页六车阵容、基地/前哨站、H展开/兑换、其他旧Hero逻辑和模拟器其余RMUC机制仍需后续逐项迁移。背景页看到英雄不代表P性能选项仍旧存在，也不能宣称全客户端已适配。
- 哨兵观测入口用于本地调试，不据此宣称官方裁判端允许7号终端注册；不得远程操控哨兵。本次限制P性能和键鼠入口，其他旧上行topic尚未完成全面角色隔离。
- 模拟器仍按单个当前机器人视角维护性能，不是所有机器人的独立完整性能引擎。选择不同性能后的血量、功率、冷却等规则联动未在此实现，准备阶段默认性能下发时机也需真实裁判系统验证。
- 本地显示和声音等设置仍为运行时设置，未新增配置持久化；真实裁判系统、实体图传、模块装配和硬件键鼠链路尚未验收。
